# Бесплатный сервер для «Бункера»

Сетевой сервер игры работает на **Cloudflare Workers + SQLite Durable Objects**. Это бесплатный облачный сервисный слой: создателю комнаты и участникам не нужно держать компьютер включённым.

## 1. Создать Worker

1. Создайте аккаунт Cloudflare и оставьте его на плане **Workers Free**. Не переходите на Workers Paid.
2. Установите актуальную LTS-версию Node.js.
3. Скачайте репозиторий или откройте его локальную копию.
4. В терминале перейдите в папку **cloudflare** и выполните:

\`\`\`bash
cd cloudflare
npm install
npx wrangler login
npx wrangler deploy
\`\`\`

5. После публикации Wrangler покажет адрес примерно такого вида:
   **https://bunker-room-server.<ваш-поддомен>.workers.dev**.

При первой публикации Wrangler создаст SQLite-backed Durable Object по миграции из wrangler.toml.

## 2. Подключить сайт к Worker

Откройте файл **cloudflare-config.js** в корне репозитория и укажите полученный адрес:

\`\`\`js
window.BUNKER_API_BASE = "https://bunker-room-server.<ваш-поддомен>.workers.dev";
window.BUNKER_TURNSTILE_SITE_KEY = "";
\`\`\`

Адрес должен начинаться с **https://** и заканчиваться на **.workers.dev**. Не добавляйте в этот файл секреты или пароли: он загружается в браузер каждого игрока.

После изменения сохраните файл и отправьте его в GitHub. Только после этого имеет смысл включать обновлённый фронтенд из ветки **security/cloudflare-backend** в основную ветку **main**.

Проверить, что Worker опубликован, можно по адресу:

**https://bunker-room-server.<ваш-поддомен>.workers.dev/health**

Ожидаемый ответ: **{"ok":true,"service":"bunker-room-server"}**.

## 3. Включить защиту от ботов (рекомендуется)

В проект встроена поддержка **Cloudflare Turnstile**. Она необязательна, но полезна для публичного сайта: проверка выполняется при создании комнаты и новом входе по коду. Возобновление своей сохранённой сессии повторную проверку не требует.

1. В панели Cloudflare откройте Turnstile и создайте виджет для hostname **netomur.github.io**.
2. Скопируйте публичный **Site Key** в cloudflare-config.js:
   **window.BUNKER_TURNSTILE_SITE_KEY = "ВАШ_SITE_KEY";**
3. В терминале, находясь в папке cloudflare, выполните:

\`\`\`bash
npx wrangler secret put TURNSTILE_SECRET_KEY
\`\`\`

4. Вставьте секретный **Secret Key** в терминал, когда Wrangler попросит его.

Публичный Site Key можно хранить в cloudflare-config.js. Secret Key хранится только в Cloudflare Worker и никогда не должен попадать в GitHub или HTML.

Если Turnstile не нужен, оставьте Site Key пустым и не создавайте секрет TURNSTILE_SECRET_KEY. Не настраивайте только одну половину пары: если серверный секрет задан, а публичный ключ не указан на сайте, создание и вход в комнаты будут отклоняться.

Бесплатный Turnstile подходит для небольших публичных сайтов; на бесплатном плане доступно до 20 виджетов и неограниченное число проверок. Подробности: https://developers.cloudflare.com/turnstile/plans/.

## 4. Discord (необязательно)

Игра работает и без Discord — игроки могут вводить обычные имена. Чтобы восстановить вход через Discord:

1. В Discord Developer Portal откройте OAuth2 настройки приложения с Client ID, который уже указан в index.html.
2. Добавьте точный Redirect URL: **https://netomur.github.io/Bunker/**.
3. В терминале, находясь в папке cloudflare, выполните:

\`\`\`bash
npx wrangler secret put DISCORD_CLIENT_SECRET
\`\`\`

4. Вставьте Client Secret из Discord Developer Portal.

Клиент использует Authorization Code Flow с PKCE S256 и проверкой state / iss. Обмен OAuth-кода на профиль выполняется Worker-сервером. Секрет Discord не хранится в браузере и не коммитится в репозиторий. В игре сохраняются только имя и ссылка на аватар; токен Discord не сохраняется.

## 5. Проверить игру

После публикации Worker и настройки cloudflare-config.js:

1. Откройте GitHub Pages в обычном браузере.
2. Создайте тестовую комнату.
3. Откройте сайт во втором браузере или приватном окне и войдите по 8-значному коду.
4. Проверьте, что каждый видит свои закрытые карточки, а чужие значения появляются только после раскрытия.
5. Начните голосование и проверьте, что до завершения никто не видит чужой выбор. После завершения результаты должны появиться у всех.
6. Проверьте действия ведущего: смену ведущего в лобби, раскрытие карточек, правки, выбывание и финальные вопросы.

## Что защищает сервер

- Полные значения карточек хранятся в Durable Object. Обычный игрок получает только свои закрытые карточки и раскрытые карточки остальных.
- Ведущий может видеть скрытые карточки через функцию «Подсмотреть скрытое». Поэтому ведущим назначайте только тех, кому доверяете.
- Незавершённые голоса скрываются от всех, включая ведущего. После завершения голосования результаты открываются.
- Игровые команды проверяются сервером: обычный игрок не может отправить команду ведущего, изменить чужую карточку, проголосовать за себя или голосовать после завершения голосования.
- Подключение идёт по HTTPS/WSS. Коды комнат имеют 8 символов; на сервере действуют ограничения частоты запросов и максимального размера сообщения.
- Сессия участника подтверждается случайным токеном. На сервере хранится его хэш, а сам токен остаётся в локальном хранилище браузера участника.
- Комната удаляется через 24 часа бездействия.
- В браузер не передаются Discord Client Secret, Discord access token или секрет Turnstile.

## Что это не гарантирует

Это защита для дружеской игры, а не система для хранения секретов или личных данных.

- Cloudflare — оператор сервиса и доверенная сторона: состояние комнаты хранится у него. Это не сквозное шифрование от провайдера.
- Ведущий имеет доступ к скрытым карточкам. Нельзя технически запретить ему подглядывать, сохранив эту игровую возможность.
- Участник может сфотографировать экран, переслать код комнаты или рассказать увиденное. От этого программная защита не спасает.
- Не вводите реальные адреса, телефоны, пароли, медицинские сведения или другие конфиденциальные данные в игровые карточки.

## Бесплатные лимиты

На Workers Free действуют суточные лимиты. Для Durable Objects SQLite free tier включает:
- 100 000 запросов в сутки;
- 13 000 GB-s вычислений в сутки;
- 5 млн прочитанных строк в сутки;
- 100 000 записанных строк в сутки;
- 5 GB SQLite-хранилища.

У самого Workers Free также есть лимит 100 000 запросов в сутки. При превышении лимита на бесплатном плане соответствующие операции начинают возвращать ошибку до сброса суточной квоты; они не должны автоматически переводиться на платный тариф.

Удерживайте аккаунт на Workers Free и не включайте платный план. Для небольшой компании эти квоты — разумная отправная точка, но они не являются гарантией доступности при резком росте нагрузки. Официальные ограничения и тарифы:

- Workers: https://developers.cloudflare.com/workers/platform/limits/
- Durable Objects: https://developers.cloudflare.com/durable-objects/platform/pricing/
- SQLite Durable Objects limits: https://developers.cloudflare.com/durable-objects/platform/limits/
- WebSocket hibernation: https://developers.cloudflare.com/durable-objects/best-practices/websockets/

## Откат

Текущая работа находится в ветке **security/cloudflare-backend**. Не объединяйте её с **main**, пока Worker не опубликован и адрес не указан в cloudflare-config.js. Основная версия игры остаётся нетронутой. Если новая версия не понравится, просто продолжайте использовать main или закройте Pull Request.
