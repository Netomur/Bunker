## ☢ Что это за игра?

**«Бункер»** — браузерная многопользовательская игра на выживание для компании друзей. После катастрофы группа людей пытается попасть в убежище, но свободных мест хватит не всем.

У каждого участника есть персонаж со случайными характеристиками. Игроки постепенно раскрывают информацию о себе, обсуждают кандидатов и голосуют за исключение. Когда остаётся нужное количество выживших, ведущий проверяет, сможет ли бункер обеспечить им жизнь.

Игра запускается прямо в браузере. Устанавливать отдельную программу или создавать аккаунт не обязательно.

## ▶ Как начать

1. Откройте **[Бункер](https://netomur.github.io/Bunker/)**.
2. Введите игровое имя. Вход через Discord необязателен.
3. Нажмите **«Создать комнату»** и выберите набор **«Стандартный»**.
4. Отправьте друзьям шестизначный код комнаты.
5. Когда все подключатся, ведущий запускает партию.

Чтобы присоединиться к игре, введите имя и код в разделе **«Войти в комнату»**.

## 🎮 Как проходит партия

**Лобби.** Создатель комнаты становится ведущим. Он может передать эту роль другому игроку, решить, участвует ли сам ведущий, и установить количество людей, которые должны остаться в финале.

**Раздача персонажей.** При старте каждому участнику случайно назначаются характеристики. Также для всей партии выбираются сюжет, размер бункера и планировка помещений.

**Раунды.** Ведущий чередует показ характеристик и голосование на выбывание. В фазе показа каждый живой игрок открывает одну свою карточку. В голосовании игроки выбирают кандидата; результаты становятся видны после завершения голосования ведущим.

**Выбывание.** Ведущий отмечает игрока, который покидает убежище. При необходимости его можно вернуть. Специальные возможности персонажей могут повлиять на ход партии.

**Финал.** Когда остаётся заданное количество участников, игроки открывают оставшиеся характеристики, а ведущий отвечает на вопросы о состоянии бункера.

**События и состояние убежища.** Ведущий может публиковать события из набора или создавать разовые объявления, которые остаются поверх игры до закрытия ведущим. Отдельно отображаются люди / места, провиант, воздух и доступность помещений. Все эти значения ведущий может менять прямо во время партии. Счётчик людей / мест не заменяет условие «Сколько должно остаться в финале» в лобби: это два независимых показателя.

## 🧍 Характеристики персонажа

В игре используется 12 категорий:

| Категория | Что может выпасть |
|---|---|
| Пол | Мужчина или женщина; дополнительно может указываться возраст. |
| Раса | Вид или происхождение персонажа. |
| Телосложение | Тип телосложения и рост. |
| Человеческая черта | Особенности характера и поведения. |
| Профессия | Специальность и уровень мастерства. |
| Здоровье | Состояние здоровья и возможные ограничения. |
| Хобби / увлечение | Занятия и интересы, иногда с уровнем мастерства. |
| Фобия / страх | То, чего персонаж боится. |
| Крупный инвентарь | Большой предмет или ресурс. |
| Малый инвентарь | Небольшая вещь, которую персонаж взял с собой. |
| Доп. сведение | Дополнительный факт о персонаже. |
| Спец. возможность | Особое действие, способное повлиять на партию. |

## 🏚 Встроенный набор «Стандартный»

В релизе один встроенный набор — **«Стандартный»**. Он задуман как нейтральная основа для обычной партии, без привязки к мемам, фандомам или внутренним шуткам конкретной компании.

В набор входят три сценария катастроф, базовые варианты всех характеристик, дополнительные параметры возраста, роста и мастерства, специальные возможности, размеры бункера, планировки помещений и финальные вопросы.

Сюжет, размер и планировка выбираются при старте партии и одинаковы для всех игроков.

## ⚖ Финальная оценка и приоритеты

У каждого финального вопроса есть приоритет от **1 до 10**.

Пример записи в редакторе:

```text
Починена ли дверь в бункер? [10] | да
Есть ли чистая питьевая вода? [10] | да
Хватит ли запасов еды на весь срок? [8] | да
Есть ли необходимые лекарства? [5] | да
Сможете ли прожить весь год? [1] | да
```

После вертикальной черты указывается ответ, необходимый для выживания: `да` или `нет`.

- Совпавший ответ приносит количество баллов, равное приоритету.
- Несовпавший ответ не приносит баллов.
- Итоговый процент — набранные баллы относительно суммы приоритетов всех вопросов.
- Для победы необходимо набрать не менее **70%**.
- Вопрос с приоритетом **10 — критический**: неправильный ответ хотя бы на один такой вопрос означает поражение независимо от общего процента.
- Приоритеты **8–9** сильно влияют на оценку, но сами по себе не означают автоматическое поражение.
- Если приоритет не указан, используется вес **1**.

## 🛠 Собственные наборы

На главной странице можно создать собственный набор карточек. В редакторе доступны сюжет, все характеристики, параметры возраста / роста / мастерства, размер бункера, планировки, финальные вопросы, начальные показатели убежища и каталог событий.

| Что добавляем | Как записывать |
|---|---|
| Варианты характеристики | Один вариант на новой строке. |
| Несколько сюжетов | Разделять отдельной строкой `---`. |
| Подсказка к карточке | `Инженер [Умеет чинить генераторы]`. |
| Размер бункера | Каждый вариант — с новой строки. |
| Планировка | Каждый вариант планировки — с новой строки. Внутри варианта названия помещений разделяются запятыми, точками с запятой или переносами строк. |
| Финальный вопрос | `Вопрос [приоритет] \| да/нет`. |
| Начальные показатели | Число мест — целое; провиант и воздух — числа. Норма провианта и воздуха в партии начинается со 100%. |
| Событие набора | `Название \| текст для игроков \| заметка ведущему`. Одна строка — одно событие; заметка необязательна. |

Собственные наборы хранятся **локально в браузере** и не синхронизируются между устройствами. Для переноса используйте **«Экспорт»** и **«Импорт»**.

> **Совместимость:** корректные пользовательские наборы, уже сохранённые в браузере, сохраняются при миграции. Тем не менее рекомендуем периодически делать резервную копию через «Экспорт», особенно перед очисткой данных браузера.

## 🎛 Инструменты ведущего

- **Подсмотреть скрытое** — увидеть закрытые значения характеристик.
- **Режим правок** — заменить значение случайным, изменить вручную, поменять значения между игроками или открыть / скрыть карточку.
- **Управление игроками** — назначить ведущего, исключить участника или вернуть выбывшего.
- **Управление партией** — завершить голосование, отметить выбывшего или закончить игру досрочно.
- **Финальные ответы** — отметить «Да» или «Нет» для каждого условия и получить итоговый процент.
- **События** — выбрать событие из набора или создать разовое. Опубликованное событие показывается всем участникам поверх игры; закрыть его может только ведущий.
- **Заметка ведущему** — служебная подсказка, которая не отображается в интерфейсе игроков. Не используйте её для секретов: сетевые сообщения не защищены от просмотра.
- **Показатели убежища** — редактировать количество людей и мест, текущий провиант и воздух, а также их базовую норму. Значения выше 100% можно использовать для учёта запасов.
- **Помещения** — закрывать, возвращать в доступ и добавлять новые. Это ручной учёт для RP, а не автоматическое моделирование последствий.

## 🔌 Технологии и сетевое устройство

Проект — статический сайт на **HTML, CSS и JavaScript**, опубликованный через GitHub Pages. Для обмена состоянием игры используются MQTT-соединения через WebSocket. Вход через Discord — дополнительная функция.

Особенности текущей реализации:

- Счётчики убежища — ручные показатели ведущего. Игра не расходует провиант и воздух автоматически, не бросает кубики и не применяет последствия событий за ведущего.
- Список помещений фиксирует доступность комнат; закрытие комнаты не переписывает выбранную планировку и само по себе не блокирует игровые действия.
- Число людей автоматически уменьшается при отметке «Выбыл» и увеличивается при «Вернуть». Ведущий может вручную скорректировать его, например для учёта NPC.
- Комнату создаёт браузер игрока-хоста. Его вкладка должна оставаться открытой во время партии.
- Хост и ведущий — разные роли.
- При потере хоста управление сессией может перейти к другому участнику.
- Для связи используются публичные сторонние MQTT-брокеры.
- Скрытые карточки маскируются в интерфейсе, но копия состояния партии передаётся подключённым клиентам. Это не система защиты от намеренного читерства.
- Код комнаты — идентификатор комнаты, а не пароль.
- Сетевые сообщения не являются сквозным приватным каналом; оператор брокера может обрабатывать их содержимое.

Для подробностей см. [PRIVACY.md](PRIVACY.md).

## 🔒 Данные и конфиденциальность

Игра использует GitHub Pages, jsDelivr, Discord (по желанию) и публичные MQTT-брокеры. В браузере сохраняются имя, настройки, пользовательские наборы и на устройстве хоста — копия состояния комнаты. При добровольном входе через Discord сохраняются ID, имя и URL аватара.

Не вводите в игру реальные адреса, номера телефонов, документы, пароли, медицинские, финансовые или иные конфиденциальные сведения. Публичные брокеры являются сторонними сервисами, не контролируемыми автором проекта.

Полное описание данных, сторонних сервисов, локального хранения и ограничений использования находится в [PRIVACY.md](PRIVACY.md).
